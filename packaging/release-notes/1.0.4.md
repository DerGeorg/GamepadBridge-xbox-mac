## The permission guidance stays on screen

1.0.3 put the instructions in an alert, and pressing its button dismissed
it — so they vanished at the moment System Settings opened and they were
needed. It is a proper window now: it floats above Settings, stays until
the permission is granted, notices that by itself, and offers to restart.

## Registering with Input Monitoring, properly this time

Asking through `IOHIDRequestAccess` and opening a HID manager still left
GamepadBridge out of the list. The manager was never given a run loop,
and devices are only opened once one turns — it is that attempt, not the
open call, which raises the request. Fixed.

Because that is a macOS behaviour rather than something this app fully
controls, the window also has a **Show Me the App** button. It reveals
GamepadBridge in the Finder so it can be dragged straight onto the list,
which works whatever macOS decides to do.

## Elsewhere

The menu bar now says "Virtual gamepad refused" when the system turns the
device down, rather than leaving it in a log. That is what made this
diagnosis possible at all.

## Install

```sh
brew tap dergeorg/tap https://gitlab.dergeorg.at/mac/homebrew-tap.git
brew trust --cask dergeorg/tap/gamepadbridge
brew install --cask gamepadbridge
```

Or download `GamepadBridge.dmg` below. Signed and notarized; requires
macOS 15 or newer.
